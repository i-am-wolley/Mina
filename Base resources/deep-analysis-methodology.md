# Deep portfolio analysis — methodology (repeatable)

First built 2026-09-26, in response to: "go deep analyse... spread across caps, industries, countries, markets... PEs... growth... risks... fund look-through... goal fit." This is the process to re-run when asked to refresh it (funds' disclosed portfolios change monthly; company fundamentals move constantly) — not a one-off script, a checklist.

## What this produces

Four mock-data files, all keyed by real `instrument_id` (from `mock-data/instruments.js`) so `index.html` can join against them with plain lookups — never inventing a number in the render layer, same discipline as every other real figure in this app:

- **`mock-data/research-profiles.js`** → `INSTRUMENT_RESEARCH` — per-instrument: `marketCapTier`, `marketCapUsdBn`, `country` (true domicile, not listing currency), `peRatioTTM`/`peRatioForward`, `growthOutlook: {y2,y3,y5}` (real analyst-consensus CAGR), `growthBasis` (what the number actually is and its caveats), `keyRisks: [...]`, `thesisNote` (neutral, descriptive — never a buy/sell view), `source`, `asof`.
- **`mock-data/fund-holdings.js`** → `FUND_LOOKTHROUGH` — per-fund: `fundName`, `category`, `capTilt`, `fundLevelPE` (only if the AMC itself discloses one — never re-derived from the top10), `top10: [{name, isin, weight, sector, marketCapTier, country}]`, `top10CoveragePct`. Debt/liquid funds get a different shape instead (`instrumentType: 'debt'`, `holdingType`, `avgMaturityDays`, `creditQuality`). `FUND_LOOKTHROUGH_ALIAS` maps folios/plans that share one underlying fund (e.g. Vinod's and Keerthana's HDFC Sensex Direct-plan folios; both Nifty Next 50 trackers, since HDFC's and ICICI's versions hold the identical index) to one canonical entry — don't re-research the same fund twice under different keys.
- **`mock-data/sector-outlook.js`** → `SECTOR_PARENT_MAP` (normalizes every sub-sector string, from both `instruments.js`'s `sector` field and fund look-through's sector strings, onto one of ~20 parent buckets), `SECTOR_OUTLOOK` (growth drivers/risks/outlook per parent sector), `INDEX_PE_BENCHMARKS` (Nifty 50 / S&P 500 / MSCI ACWI ex-US trailing P/E).
- **`mock-data/geography-outlook.js`** → `GEOGRAPHY_OUTLOOK` — one entry per country the household actually has real exposure to (via true domicile, not currency): GDP growth outlook, market valuation note, risks.

## The checklist (re-run in this order)

**1. Master holdings list.** Read `mock-data/positions.js` + `mock-data/instruments.js` fresh — the exact list of instrument_ids drifts every reprice pass (new purchases, switches, folio splits). As of 2026-09-26: 10 Indian direct stocks, 14 US/foreign stocks + 1 RSU (AB InBev), ~10 distinct mutual funds (aliasing shared folios/plans), 3 FDs + EPF + Gold (lighter treatment, see below).

**2. Company research — per direct stock/RSU.** For each: real market cap + SEBI-style cap tier (Large=top 100 by market cap, Mid=101-250, Small=251+, Micro=beyond that/thin coverage), true country of domicile (check this explicitly for ADRs/foreign-listed names — TSM is Taiwan, ASML is Netherlands, AB InBev/BUD is Belgium, despite all three trading as USD-denominated US listings), trailing/forward P/E, analyst-consensus 2/3/5yr growth outlook (revenue or EPS CAGR — use whatever real consensus sources exist: Screener.in/Trendlyne/GuruFocus for Indian names, StockAnalysis.com/Simply Wall St/Zacks for US names), 2-4 real key risks, a neutral 2-3 sentence thesis. **Never fabricate a consensus figure for a stock with no real analyst coverage** (this session's two India micro-caps, K.P. Energy and Solex Energy, had none — their growth outlook is explicitly labeled as inferred from company guidance, not consensus, with lower confidence disclosed in `growthBasis`). Gold gets the same shape with `growthBasis` relabeled "Gold price consensus" (not earnings-based) and real bank/WGC price targets. FDs/EPF don't need a research-profile entry — their real contracted rate/statutory rate already lives in `instruments.js` and is used directly.

**3. Fund look-through — per distinct fund.** Pull each fund's latest real, publicly disclosed top-10 holdings with weights (AMC factsheet, Value Research Online, Moneycontrol, Groww, Tickertape, or — for VXUS — Vanguard's own fact sheet PDF). Also capture category, cap tilt, and fund-level P/E **only if the factsheet itself discloses one**. Two funds tracking the identical index (e.g. HDFC's and ICICI's Nifty Next 50 trackers) share one research entry via `FUND_LOOKTHROUGH_ALIAS` — don't research the same portfolio twice. **Disclose gaps honestly**: this pass found HDFC Sensex's ranks 6-10 only via a same-index proxy fund (weights approximate), quant Flexi Cap's high portfolio churn meant only a verified top-5 (ranks 6-10 genuinely not found, not guessed), and a couple of funds had a cash/repo instrument mixed into their disclosed "top 10" (flagged via the `sector` field rather than silently treated as equity).

**4. Sector outlook — per parent bucket.** After step 2-3 reveal which sectors are actually represented (both directly and via look-through), research each parent sector's real growth drivers, risks, and a one-line outlook with a cited source (industry body forecasts — WSTS/SIA for semis, Gartner for software/cloud, IEA for energy/renewables/power, ICRA for Indian banking, government budget documents for India-specific sectors like defense/infrastructure, brokerage/consultancy research for others). Build `SECTOR_PARENT_MAP` by normalizing every sub-sector string that shows up in `instruments.js`'s `sector` field AND every sector string inside `fund-holdings.js`'s top10 entries — fund look-through introduces many more granular sub-sectors than direct holdings alone (e.g. "Private Banks", "PSU Banks", "NBFC" all → "Banking & Financials"). `index.html`'s `parentSectorOf()` falls back to keyword matching for anything not explicitly mapped — check that fallback still makes sense after adding new funds/holdings.

**5. Geography outlook — per country with real exposure.** Once true domicile (step 2) and fund look-through country data (step 3) reveal which countries the household actually touches, pull real GDP growth outlook (IMF World Economic Outlook — check for the freshest edition, but disclose if it hadn't published yet at research time) and a market valuation note (local index P/E vs. its own historical average) per country.

**6. Benchmark index P/Es.** Nifty 50, S&P 500, and a real MSCI ACWI ex-US (or clearly-labeled proxy) trailing P/E — used for the Exposure tab's valuation-band comparison.

## Standing rules (same as every other real number in this app)

- **Every entry needs `source` and `asof`.** No exceptions. A number without a citation doesn't go in.
- **Never invent a consensus figure.** If no real analyst coverage exists, say so in `growthBasis`/`source` and mark it lower-confidence — don't produce a plausible-looking number anyway (this cost the K.P. Energy / Solex Energy entries real accuracy disclosure, and it was the right call).
- **Never re-derive a number the source itself didn't disclose.** A fund's `fundLevelPE` is null if the factsheet doesn't state one — don't average the top-10 holdings' own P/Es to approximate it, that's a different, invented number.
- **Country = true domicile, not listing currency.** This was the single most-repeated correction needed this pass (3 of ~26 researched instruments).
- **Wording stays descriptive, never prescriptive.** Every insight card and detail panel this data feeds must read as "here's the real number / here's what's worth checking," never "sell X" or "buy Y" (AI boundaries, `CLAUDE.md`) — apply this discipline when re-writing any card copy, not just when adding new ones.
- **A gap is honest; a guess is not.** Where research genuinely couldn't find something (a fund's true top-10, a forward P/E, a 5yr growth figure), leave it `null`/disclosed rather than filling it in — this app's whole credibility rests on that line holding.

## Execution approach (what actually worked this pass)

Splitting the research into parallel delegated agents was necessary — ~40 individual holding profiles + ~10 fund look-throughs + ~15 sector outlooks + 5 geography outlooks + benchmark indices is dozens of real web searches, too much for one sequential pass in reasonable time. This session used 6 parallel research delegates (grouped: Indian stocks / US mega-caps / remaining foreign stocks+RSU / fund look-through / sectors+geography+gold+indices / a follow-up for sectors that only emerged from fund look-through data), each returning ready-to-paste JS object literals matching the exact schema above. Re-running this later should use the same grouping — it parallelizes well because each group is genuinely independent research.

## Where this feeds the app

`index.html`'s Insights tab (rebuilt 2026-09-26, see `CLAUDE.md`'s dated entry for the full design) reads all four files through thin lookup helpers (`researchFor()`, `lookthroughFor()`, `parentSectorOf()`) and a handful of pure aggregation functions (`trueStockExposure`, `sectorExposureLookthrough`, `geographyExposure`, `marketCapTierBlend`, `blendedPE`, `goalFitComparator`) — none of which compute anything beyond weighted sums/averages over these disclosed constants. If this research is refreshed, those functions don't need to change; only the four data files do.
